* Welcome!
Gaelan D'costa's GNU emacs config; there are many like it, but this one is mine.

Eventually I will understand my own config enough to explain it in a cohesive way.

This configuration is built as a nix package; as such, it assumes that nix has pre-supplied all necessary packages (which ironically, are parsed out of this file.) As such, it is also paired with whatever version of emacs that this package includes. Currently, this is GNU Emacs 30.

#+BEGIN_SRC emacs-lisp :tangle early-init.el
  ;; Maximize GC threshold during startup to minimize collection pauses;
  ;; restore to default after init completes.
  (let ((normal-gc-cons-threshold gc-cons-threshold)
        (normal-gc-cons-percentage gc-cons-percentage))
    (setq gc-cons-threshold most-positive-fixnum
  	gc-cons-percentage 1.0)
    (add-hook 'emacs-startup-hook
  	    (lambda ()
  	      (setq gc-cons-threshold normal-gc-cons-threshold
  		    gc-cons-percentage normal-gc-cons-percentage))))

  ;; Disable file-name handlers during startup (skips regex matching on
  ;; every file load); restore after so TRAMP and compressed files work.
  (let ((normal-file-name-handler-alist file-name-handler-alist))
    (setq file-name-handler-alist nil)
    (add-hook 'emacs-startup-hook
  	    (lambda ()
  	      (setq file-name-handler-alist
  		    normal-file-name-handler-alist))))

  ;; Don't compact font caches on GC (relevant for long-running daemon).
  (setq inhibit-compacting-font-caches t)

  ;; Don't resize frame to accommodate font/bar changes at startup.
  (setq frame-inhibit-implied-resize t)

  ;; Disable unnecessary GUI chrome and popup dialogs.
  (setq inhibit-startup-screen t
        use-dialog-box nil)
  (menu-bar-mode -1)
  (tool-bar-mode -1)
  (scroll-bar-mode -1)

  ;; Report startup time to *Messages*.
  (add-hook 'emacs-startup-hook
  	  (lambda ()
  	    (message
  	     "Emacs ready in %0.03f seconds with %d garbage collections"
  	     (float-time (time-subtract after-init-time before-init-time))
  	     gcs-done)))

  ;; Nix provides all packages; don't configure any package sources.
  (setq package-archives nil)
#+END_SRC

*** use-package
[[https://github.com/jwiegley/use-package][use-package]] is a wonderful package from John Wiegley which makes downloading and loading and configuring emacs packaging a much more structured affair. It can optionally download missing packages and uses a single macro to load configuration and set up bindings, regular hooks, extension associations, etc... in a consistent way.

The [[https://github.com/nix-community/emacs-overlay][emacs-overlay]] nix package also leverages use-package to know what packages it needs to download when generating an emacs package from this file.
#+BEGIN_SRC emacs-lisp :tangle no
     ;; Since (use-package) is a macro, we don't actually need to load it except
     ;; when we compile a new bytecode version of our emacs file.
     (eval-when-compile
       (require 'use-package))
     ;; (require 'diminish)                ;; if you use :diminish
     ;; (require 'bind-key)                ;; if you use :bind

     (eval-and-compile
       ;; By default if :ensure is non-nil it will use package.el to download the
       ;; package. We use a custom function to ensure that never happens.
       (defun gaelan/use-package-ensure-ignore (&rest _args) t)
       (setq use-package-ensure-function #'gaelan/use-package-ensure-ignore)

       ;; Unless we explicitly want packages loaded eagerly, rely on setting hooks
       ;; or mod or bindings to generate autoloads to only load the package on
       ;; demand.
       (setq use-package-always-defer t)
       ;; Don't assume hooks have the substring "-hook" at the end.
       (setq use-package-hook-name-suffix nil))

     ;; If debug mode is on, be more chatty. Otherwise, don't
     (if init-file-debug
	 (setq use-package-verbose t
	       use-package-expand-minimally nil
	       use-package-compute-statistics t)
       (setq use-package-verbose nil
	     use-package-expand-minimally t))
#+END_SRC

* Completion / Minibuffer
** Consult
Richer versions of standard Emacs commands: =consult-buffer= groups
and previews buffers, =consult-line= searches the current buffer with
live preview, =consult-ripgrep= searches the project. Acts as the
candidate-source layer — vertico/orderless handle presentation and
filtering.

Press =<= inside =consult-buffer= then a letter to narrow by type
(=b= buffers, =f= recent files, =p= project files, etc.).

** Embark
Context-sensitive action menu for anything Emacs can see. In the
minibuffer, =C-.= opens an action menu for the current candidate
instead of committing to the default action — e.g. kill a buffer
while browsing =consult-buffer=, or copy a file path during
=consult-ripgrep=. At point in a buffer, =C-.= recognises what's
under the cursor (URL, file path, symbol, org heading) and offers
relevant actions. =C-;= runs the single most useful action directly.
=C-h B= replaces =describe-bindings= with a searchable list.

=embark-consult= wires embark to consult candidate types; notably,
=embark-export= during =consult-ripgrep= exports all results to a
=grep-mode= buffer for navigation or mass editing with =wgrep=.

#+BEGIN_SRC emacs-lisp :tangle yes
  (use-package embark
    :ensure t
    :bind (("C-." . embark-act)
  	 ("C-;" . embark-dwim)
  	 ("C-h B" . embark-bindings))
    :init
    ;; Replace C-h after a prefix key with a completing-read of
    ;; available bindings, filtered by vertico/orderless.
    (setq prefix-help-command #'embark-prefix-help-command)
    :config
    ;; Hide the mode line in Embark collect/completions buffers —
    ;; it shows nothing useful in a temporary candidate list.
    (add-to-list 'display-buffer-alist
  	       '("\\`\\*Embark Collect \\(Live\\|Completions\\)\\*"
  		 nil
  		 (window-parameters (mode-line-format . none)))))

  (use-package embark-consult
    :ensure t
    :after (embark consult))

  ;; Edit grep/occur results in-place. Use embark-export during
  ;; consult-ripgrep to get a wgrep-able buffer, then C-c C-p to
  ;; enable editing, C-c C-c to commit changes across all files.
  (use-package wgrep
    :ensure t
    :custom
    (wgrep-auto-save-buffer t))
#+END_SRC

** Orderless
Enable helm-like searching via completion frameworks, where I can filter
candidates by multiple regex patterns separated by a space.

The default completions in emacs 28 are as follows:

basic :: foo|bar looks for all completions that have foo at the front, bar at
the end. It matches "foo*bar"

emacs22 :: foo|bar looks for all foo* candidates then shoves var onto the end.

partial-completion can complete multiple words, which one given as a prefix. It
will only match completions with matching prefix in the order of the prefixes
that were given. /u/mo/s will only match phrases that look like
"/usr/monnier/src" not "/monier/user/src".

So we add orderless, which allows us to complete against multiple words, but in
any order. For example, matching against /u/mo/s will match both
"/usr/monier/src" and "/usr/src/monier".

There are cases where orderless won't work, so we use basic as a fallback.

Tramp mode doesn't handle orderless well (because it involves iterating over
directory tree combination across the wire, so specifically for file navigation
we try for basic first and partial-completion after so we can get partial
intelligence without expending unnecessary effort.

#+BEGIN_SRC elisp :tangle yes
  (use-package orderless
    :demand t
    :ensure t
    :custom
    ;; Fallback to basic for completions that depend on dynamic completion
    ;; tables, whatever that is.
    (completion-styles '(orderless basic))
    ;; TRAMP can't use orderless at all, so override it to use basic and
    ;; partial completion (like /u/s/l for /usr/share/local)
    (completion-category-overrides '((file (styles partial-completion)))))
#+END_SRC
** Vertico
Vertico adds a good minibuffer UX to Emacs' default completion framework.

The defaults in Emacs 28 (~fido-mode~, ~vertical-fido-mode~) do not make it
easy for me to see potential options in various contexts, I have found.

Vertico isn't the regular tab-based completion.  It pops up a menu,
and you can navigate up and down.  A nice thing about it is you can
use C-p and C-n to pick the candidate you want instead of
contorting your input to match what you want.

#+BEGIN_SRC elisp :tangle yes
  (use-package vertico
    :defer 1
    :ensure t
    :custom
    ;; I find it annoying I try to create a new file and the vertico prompt
    ;; chooses the first existing selection; prefer the prompt value isntead.
    (vertico-preselect 'prompt)
    :config
    (vertico-mode +1))

  ;; Bundled vertico extension: DEL deletes a whole path component when
  ;; navigating file paths, rather than one character at a time.
  (use-package vertico-directory
    :after vertico
    :ensure nil
    :bind (:map vertico-map
                ("RET"   . vertico-directory-enter)
                ("DEL"   . vertico-directory-delete-char)
                ("M-DEL" . vertico-directory-delete-word))
    :hook (rfn-eshadow-update-overlay . vertico-directory-tidy))

  ;; Save minibuffer history across sessions; vertico uses this to rank
  ;; previously chosen candidates higher.
  (use-package savehist
    :defer 2
    :config
    (savehist-mode))

  ;; Track recently visited files for consult-recent-file.
  (use-package recentf
    :defer 2
    :config
    (recentf-mode +1))

  ;; Some recommended vertico UX settings
  ;; A few more useful configurations...
  (use-package emacs
    :init
    ;; Emacs 28: Hide commands in M-x which do not work in the current mode.
    ;; Vertico commands are hidden in normal buffers.
    (setq read-extended-command-predicate
  	  #'command-completion-default-include-p))

** Language Server Protocol
IDE-like functionality: completion, go-to-definition, diagnostics, and
hover docs via language-specific servers. We use Eglot (built into
Emacs 29+) rather than lsp-mode — it delegates to existing Emacs
infrastructure (corfu, xref, eldoc) instead of reinventing it.

* Productivity
** Email handling
Mail reader is notmuch via emacs's =notmuch.el= integration. Three accounts (=personal=, =work=, =old=) each have their own notmuch database under =~/mail/<account>/.notmuch=, selected via =NOTMUCH_PROFILE=. See =email.nix= in =home-manager/modules= for the per-account architecture.

Remote-host syncing happens out-of-band via =mujmap= (Fastmail) and =lieer= (Gmail), driven from the shell by =msync <account>=. emacs only reads from the local databases — it doesn't fetch from remote hosts.

=notmuch.el= itself has no built-in profile concept (verified in =notmuch-lib.el=, no =--config= threading or =NOTMUCH_PROFILE= awareness). We work around this with an =:around= advice on =notmuch--call-process= — the chokepoint for every CLI invocation =notmuch.el= makes — that injects the active profile into =process-environment= for the call duration.

    :ensure nil
    :custom
    ;; Send SMTP directly, we don't have a OS-wide MTA running.
    (send-mail-function 'smtpmail-send-it)
    (smtpmail-smtp-server "smtp.gmail.com")
    ;; TL;DR Use "Implicit TLS", most secure encrypted SMTP protocol
    ;; Port 587 - connection starts unencrypted, client requests encrypted
    ;; traffic. Called Explicit TLS. Auth happens after encryption established.
    ;; Port 465 - connection must be encrypted via TLS from the get-go, there
    ;; is no unencrypted traffic. Called Implicit TLS.
    ;;
    ;; The history of which port to use is convoluted, and a lot of advice on
    ;; the internet is outdated or misinformed. For example, a lot of advice
    ;; claims that port 465 is for an older encryption protocol, SSL, and 587 is
    ;; for TLS. This does not appear to be true.
    ;; As long as the server is configured properly, both 587 (STARTTLS) and
    ;; port 465 (Implicit TLS) are secure. The problem is a 587-based SMTP
    ;; server _could_ disallow encrypted traffic, and the client could allow
    ;; unencrypted traffic. That is a risk.
    ;; See: https://mailtrap.io/blog/starttls-ssl-tls/
    ;;
    ;; We are choosing the protocol which require TLS from the start.
    (smtpmail-smtp-service 465)
    ;; This actually means TLS, if the remote server supports it.
    (smtpmail-stream-type 'ssl))

** Window Management

=winner-mode= records every window configuration change in a ring
buffer, so you can undo and redo layout changes. Useful any time
magit, cider, or a help buffer rearranges your layout unexpectedly.

#+BEGIN_SRC emacs-lisp :tangle yes

    :ensure nil
    :bind (("C-c [" . winner-undo)
           ("C-c ]" . winner-redo))
    :config

#+END_SRC

=tab-bar-mode= gives each Emacs frame named tabs, each with its own
independent window layout. =C-x t 2= clones your current tab into a
new one, =C-x t r= renames it, =C-x t 0= closes it.

#+BEGIN_SRC emacs-lisp :tangle yes

    :ensure nil
    :config
